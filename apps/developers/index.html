What happens next

    

      
Users connect once
Any CIP-30 wallet: Lace, Eternl, Vespr, Typhon and others. One signature creates their Strike account and a trading key that can't withdraw.

      
You earn on every fill
Your builder fee is added to each order. Strike collects it on every fill and credits it to your Strike account. Users always see it before they confirm.

      
Track every integration
Traders and volume per app, verified against Strike's public fill history; connected wallets as reported by the widget.

Questions

    

      
Do I need a backend or API keys?
No. The panel talks directly to Strike from the user's browser. Your only credential is your public builder code.

      
Can my app withdraw user funds?
No. The trading key created at connect can place orders but can't withdraw: withdrawals need the user's own wallet signature and only go back to their wallet. The browser holds the key so no script can copy it, and it's forgotten after 30 minutes without activity. Deposits are checked before the user signs.

      
What should I charge?
5 bps (0.05%) is a good place to start. Strike allows up to 100 bps, and the panel shows every fee before the user confirms, so low fees tend to win volume.

      
Full app or trade ticket?
The ticket fits next to your own content. The full app (variant="app") needs a whole screen, like a wallet's Perps tab: markets, chart, order book, every order type and position tools. On narrow screens it switches to a phone layout by itself.

      
Does it work in a wallet extension or mobile wallet?
Yes, it's a standard web component. In an extension popup set width="368"; if your CSP blocks remote scripts, bundle the ESM build (strike-everywhere.js) instead.

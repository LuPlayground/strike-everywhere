Safe by
default

    
Trading inside someone else's website changes the trust boundaries. These are ours, stated plainly.

    

      
Keys stay in the browser
The trading key is generated client-side and never leaves it. No server, ours included, ever holds it.

      
The key can't withdraw
Withdrawals need the user's own wallet signature, and Strike only pays them back to that wallet.

      
Deposits checked before signing
Strike's unsigned transaction is decoded first: exactly the requested ADA, one output, no tokens. Anything else and the widget refuses to ask for a signature.

      
Fees capped by the user
The fee cap is part of the message the user signs. Strike rejects any order above it, whoever the host is.

      
Keys limited to the session
Strike issues keys that don't expire, so the widget enforces its own lifetime, and reconnecting rotates the key.

      
Isolated from the host
A Shadow DOM keeps host styles out. The known limit: a malicious host page could place trades with the in-memory key, but not withdraw. Details in SECURITY.md.

How it works

From one tag to builder fees in four steps

Hover a step to see what happens under the hood. Every call goes from the user's browser straight to Strike; no server ever holds a trading key.

01 / EMBED

Drop in one tag

Add the script and a <strike-trade> tag with your builder code.

Hover to reveal
  • Shadow-DOM web component: host CSS can't break it
  • Strike's own design language: chart, order book, stop & TWAP orders, ~52 KB gzipped
  • Live mark prices and funding for every Strike market via WebSockets
<strike-trade builder-code="…">
02 / CONNECT

One signature

Users pick Lace, Eternl or any CIP-30 wallet and sign once. Strike creates the account.

Hover to reveal
  • Browser generates an Ed25519 trading key
  • Wallet signs Strike's consent (fee cap, key, builder) via CIP-30 COSE
  • New wallets are detected and told about the $100 first-deposit rule up front
POST /auth/builder/verify-signature
03 / TRADE

Deposit & trade

ADA deposits are checked before signing; orders carry the partner's builder fee.

Hover to reveal
  • Strike builds the deposit; the widget decodes it: exact ADA, one output, no tokens
  • Wallet witnesses spliced byte-for-byte, so the tx id never changes
  • Market/limit, TP/SL, leverage, liquidation estimate, all fees shown first
X-Builder-Fee-Bps: 5
04 / EARN

Verified volume

Strike charges your builder fee on every fill. The dashboard shows which partner site the volume came from.

Hover to reveal
  • Volume: Strike's public fills on orders the widget registered first
  • Funded: settled deposits in Strike's history; connected is widget-reported
  • Builder fees computed as notional × fee bps
GET /v2/history/fill?account_id=…

Security
Built so partners can't touch user funds

    

      
Keys stay in the browser
The trading key is generated client-side and can't withdraw: withdrawals need the user's own wallet signature and only go back to that wallet.

      
Deposits checked before signing
Strike's unsigned transaction is decoded and verified: exact amount, single output, no tokens. Otherwise the widget refuses.

      
Fees capped by the user
The fee cap is part of the message the user signs. Strike rejects any order above it, whoever the host is.
